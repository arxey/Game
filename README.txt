Выполнены все пять основных этапов и все четыре задания со звёздочкой.

Были доступны два PDF, но не выданная преподавателем заготовка. Поэтому это

1. БЫСТРЫЙ ЗАПУСК

Распакуйте ВЕСЬ архив. Откройте терминал в папке space_shooter, где лежит main.py.

Windows:
    py -3 -m pip install -r requirements.txt
    py -3 main.py

Linux / macOS:
    python3 -m pip install -r requirements.txt
    python3 main.py

На системе с командой python вместо py/python3:
    python -m pip install -r requirements.txt
    python main.py

После установки можно запускать start.bat (Windows) или ./start.sh (Linux/macOS).
Если системе запрещена установка пакетов в общий Python, используйте отдельную
среду. Пример для Windows:
    py -3 -m venv .venv
    .venv\Scripts\python.exe -m pip install -r requirements.txt
    .venv\Scripts\python.exe main.py

Linux/macOS:
    python3 -m venv .venv
    .venv/bin/python -m pip install -r requirements.txt
    .venv/bin/python main.py

start.bat/start.sh автоматически используют .venv, если она создана рядом.
Ошибка No module named pygame означает: пакет не установлен именно в том
интерпретаторе Python, которым запускается main.py. Используйте одну и ту же
команду Python для установки и запуска. Нужен пакет pygame-ce, модуль — pygame.

2. УПРАВЛЕНИЕ

    Стрелки влево / вправо — перемещение корабля.
    Пробел                 — непрерывная стрельба.
    F1                     — подписи состояний и сетка 48×48.
    L                      — переключение ограничения 60 / 20 FPS.
    = или +                — добавить 50 обычных врагов.
    G                      — сетка / полный перебор столкновений.
    R                      — новая игра после окончания.
    Esc                    — выход.

Вначале 8 обычных врагов и 2 турели. Три нажатия = дают ровно 158 обычных
врагов; турели считаются отдельно. Начальные жизни игрока — 3. После урона
корабль мигает и не получает повторный урон в течение 1.5 секунды.

В HUD формат «Пули: 7 / 20» означает 7 активных объектов и 20 созданных.
Аналогично показаны частицы и пули турелей. Счётчик проверок учитывает только
точные проверки пуль игрока против врагов и турелей за последний кадр.

3. ПЯТЬ ЭТАПОВ ПРАКТИКИ

Этап 1. Delta time — main.py, entities.py, enemy.py.
dt ограничен 0.05 секунды. Корабль: 300 px/s; пуля: 600 px/s;
патруль: 120 px/s; погоня по вертикали: 60 px/s; атака: 400 px/s.
Перезарядка 0.15 секунды. Остаток времени переносится между выстрелами,
чтобы кадры по 16–17 мс не снижали частоту стрельбы.

Этап 2. Пул пуль — pool.py, entities.py, game.py.
Pool(Bullet, 20); get() выдаёт и активирует свободный объект, active()
обходит активные. При нехватке пул расширяется. После попадания или вылета
пуля выключается и позже переиспользуется. Размер пула показан в HUD.

Этап 3. Состояния — enemy.py.
Patrol: движение влево-вправо; игрок ближе 100 px → Chase.
Chase: движение к игроку; ниже середины экрана → Attack;
игрок дальше 200 px → Patrol.
Attack: пикирование 400 px/s; за нижней границей → возрождение, Patrol.
Flee: после попадания при 1 HP; движение вверх 180 px/s в течение 2 секунд.
Затем враг возрождается в верхней области с 3 HP и состоянием Patrol.
Возрождение после бегства — принятое решение, чтобы враг не остался
патрулировать за пределами экрана. Очко начисляется только за уничтожение.
Enemy.update() делегирует работу state.update(), без цепочки условий поведения.
Имя и цвет каждого состояния видны при F1.

Этап 4. Пространственная сетка — grid.py, game.py.
Клетка 48 px; clear(), add(), near(x, y). Пуля получает кандидатов из своей
и восьми соседних клеток. Для быстрого движения проверяются окрестности
обоих концов отрезка за кадр. Проверка относительного отрезка движения
предотвращает пролёт пули сквозь встречного атакующего врага при 20 FPS.
Порядок кандидатов сохраняется, поэтому перекрывающиеся враги получают
попадания так же, как при полном переборе. G меняет режим, F1 рисует клетки.

Этап 5. Частицы — entities.py, game.py.
Pool(Particle, 300), тот же Pool без специальных изменений.
15 искр цвета состояния при каждом попадании; дополнительно 40 золотых искр
при уничтожении, то есть 55 на смертельное попадание. Жизнь искры 0.3–0.8 s,
скорость 50–250 px/s. После окончания жизни active=False.

4. ВСЕ ЗАДАНИЯ СО ЗВЁЗДОЧКОЙ

Очередь событий — event_queue.py, game.py:
on_hit меняет здоровье и публикует enemy_hit / enemy_killed. Начисление счёта,
искры и выпадение бонуса — отдельные подписчики. process() вызывается после
проверки столкновений. Событие хранит неизменяемые координаты попадания,
потому что к обработке враг уже мог возродиться в другой точке.

Компоненты — components.py:
GameObject обновляет независимые Health и Shooter. Из этих двух компонентов
собрана неподвижная турель, стреляющая вниз каждые 1.2 s. Пули турелей
движутся 250 px/s и тоже берутся из пула. У турели 3 HP.

Бонусы — entities.py, game.py:
При уничтожении с вероятностью 25% появляется падающий квадрат «3».
Подбор включает тройной выстрел на 5 секунд. Повторный подбор обновляет
таймер до 5 секунд. Обычный выстрел возобновляется автоматически.

Жизни игрока — entities.py, game.py:
Пуля турели или столкновение с пикирующим врагом отнимает жизнь.
Несколько попаданий за кадр не отнимают сразу несколько жизней.
При 0 жизней мир замирает и появляется «Игра окончена». R перезапускает игру.

5. ПРОВЕРКА

Из папки проекта, тем же интерпретатором Python:
    python -m unittest discover -v

35 автоматических тестов. Дополнительные зависимости для тестов не нужны.
Тесты используют pygame без реального дисплея.

Воспроизводимое сравнение сетки и перебора, а также времени update+draw:
    python benchmark.py

Пример сохранён в docs/benchmark.json. На одинаковой сцене из 158 врагов
и 40 пуль: перебор 3160 проверок, сетка 221; уменьшение в 14.3 раза.
Результат попаданий совпадает. 40 пуль нужны только для нагрузочного стенда;
в тесте обычной стрельбы за 30 секунд пул остаётся размером 20.

За 30 секунд при 20 и 60 FPS, а также при кадрах 16–17 мс — 200 выстрелов,
создано всего 20 пуль. 100 разделённых во времени взрывов сохраняют размер
пула частиц 300. Одновременный очень большой всплеск расширит пул до пикового
числа активных объектов; после прогрева объекты снова используются.

Автоматическая проверка настоящего главного цикла:
    python main.py --headless --frames 120 --screenshot frame.png

Проверка руками:
1) Зажать пробел и двигаться; нажать L. Скорость не меняется, картинка реже.
2) Стрелять 30 секунд. Общий размер пула пуль держится около 20.
3) Включить F1. Сравнить цвета и подписи четырёх состояний; два попадания
   в обычного врага оставляют 1 HP и включают бегство.
4) Нажать = три раза. Переключать G во время стрельбы, сравнивая проверки.
5) Попасть во врагов несколько раз. Наблюдать искры и размер пула частиц.
6) Подобрать «3»: три пули, затем через 5 секунд снова одна.
7) Дать турели или пикирующему врагу попасть в корабль. Проверить жизни,
   окончание игры после третьего урона и перезапуск клавишей R.

Время update+draw в docs/benchmark.json измерено на Surface без окна.
Это не измерение реального FPS и не гарантия 60 FPS на любом компьютере.
Визуальная проверка в этой среде выполнена по сохранённым кадрам.

6. СОДЕРЖИМОЕ И МАТЕРИАЛЫ

main.py          — игровой цикл: ввод → update → draw.

entities.py      — Player, Bullet, Particle, Bonus.
enemy.py         — Enemy, Patrol, Chase, Attack, Flee.
pool.py          — универсальный пул объектов.
grid.py          — пространственная сетка.
components.py    — GameObject, Health, Shooter, Turret.
event_queue.py   — очередь событий и подписчики.
config.py        — размеры, цвета, шрифты, вывод текста.
benchmark.py     — воспроизводимые замеры.
tests/           — 35 проверок, выполняемых unittest.
docs/            — отчёт, результаты проверки, изображения и технический план.
assets/          — шрифт DejaVu Sans и его лицензия, для русских подписей.

gameplay.png — кадр игры после программно поданных команд управления.
debug.png — демонстрационный кадр с заранее размещёнными врагами всех
четырёх состояний, сеткой, частицами и бонусом; это иллюстрация возможностей,
а не самостоятельный результат нагрузочного теста.
